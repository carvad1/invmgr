# Архитектура

## Акции 0.6.0

- `electron/stock-web.ts`: независимый сборщик публичных источников с внедряемыми HTTP/PDF-функциями для тестов; allowlist HTTPS, два запроса одновременно, кеширование, таймауты, ограничение размера и сохранение прошлых результатов при ошибке.
- `electron/stock-web-parsers.ts`: точное сопоставление УНП и holder, документы ЕПФР, отдельные классы акций Беларусбанка, решения о дивидендах. `src/domain/stock-web.ts`: схема сохранения и правила свежести. В `stockAnalysis.web` сохраняются только данные исследования, ручные отчёты остаются независимыми.
- `electron/stock-pdf.ts` работает в Worker с ограничением времени/памяти; PDF.js + Tesseract для локального OCR (модели входят в сборку). `stock-office.ts` извлекает только нужные XML из DOCX/XLSX с ограничением распакованного размера. Чужой HTML и офисные макросы не исполняются.
- IPC `stocks:refresh`, `stocks:document`, событие `stocks:updated`. Результат сливается с последней записью инструмента; при изменении идентичности акции результат старого запроса отбрасывается. Обновление старого редактора не стирает новые веб-данные. Renderer получает прогресс по готовым акциям, тяжёлое чтение не блокирует основной процесс.

- Отдельный лениво загружаемый раздел `src/pages/Stocks.tsx`; обзор, оценка, отчётность, цена/риск, происхождение данных. Переход «Анализ» из актива-акции направляет сюда. Старый калькулятор содержит только остальные типы.
- `src/domain/stocks.ts`: ограниченный парсер JSON, выбор цены, мультипликаторы, критерии качества, FCFE/DDM, обратная оценка, технические индикаторы. `stock-schema.ts`: схема и типы отчётности/допущений/снимка/истории.
- Акции в списке наблюдения — обычные инструменты без покупок. `stockAnalysis` сохраняется в JSON инструмента и включается в существующий backup/restore без новых таблиц. Повторный импорт сохраняет пользовательские отчёты и модель.
- `src/domain/stock-import.ts`: план импорта одного/нескольких Response и пакета расширения; связи `definition`/`security_definition`, Zod-валидация до записи, история по режимам, дневное взвешивание по объёму и сводка ликвидности. `StockMarketData.tsx` показывает рынок отдельно от финансовой отчётности. Расширение собирает только разрешённые поля и связывает дополнения с текущей карточкой; данные входа не читаются.
- История отделена от бухгалтерских котировок. График загружается по требованию и прореживается; расчёты используют все точки. Импортированная цена не записывается как совершённая операция.
- Расширение 0.2.0 поддерживает акции и облигации, сбрасывает предыдущую карточку при переходе, исключает запоздалые ответы по порядку запросов. Авторизационные поля не копируются.
- В открытие внешних ссылок добавлены два точных адреса методик NYU/MSCI. Список разрешённых адресов загрузчика источников не расширен.
- Формулы, границы применимости и проверенные/непроверенные контракты описаны в `STOCK_ANALYSIS.md`.

## Интерфейс 0.4.0

- `App.tsx` управляет состоянием, навигацией и действиями. Экраны вынесены в `src/pages`, формы и диалоги — в `src/components`.
- Импортированные ответы Aigenis по облигациям живут в состоянии приложения, отдельно от постоянного портфеля. Навигация их не удаляет; закрытие приложения очищает.
- Для вставленных облигаций `bondAnalysis` выбирает цену продажи, иначе последнюю цену сделки. Доходность берётся для того же источника. Историческое значение явно отмечено как ориентир площадки, а не доступная доходность покупки или новый расчёт на сегодня.
- Локальная загрузка `portfolio:load` не ждёт сети. Обновление ставок `rates:refresh` выполняется в фоне и сохраняет прежнюю обработку ошибок источника.
- История портфеля вычисляется только при открытии графика, в отдельном Web Worker. Максимум 25 снимков за период, независимо от числа операций. Worker завершается при закрытии графика или страницы.
- Графики и подробный анализ загружаются отдельными модулями. React выделен отдельно: библиотека графиков не попадает в начальную загрузку через общую зависимость.
- Таблицы и результаты каталога показывают не более 20 строк на странице. Числовые форматтеры переиспользуются; история ставок вклада сортируется один раз на расчёт.

- Electron 44, React 19, TypeScript, Vite, Recharts, Lucide.
- SQLite из `node:sqlite` в главном процессе. Данные не хранятся в браузерном localStorage. WAL, foreign keys, synchronous FULL, транзакции для составных изменений, `user_version=1` для миграций.
- Таблицы instruments, operations, quotes, fx_rates, catalog, sync_runs, settings. Поля домена хранятся в JSON payload; идентификаторы и внешние ключи вынесены в отдельные SQL-колонки. Схемы домена проверяются Zod перед сохранением и при восстановлении.
- Движок расчётов `src/domain/finance.ts` чистый: используется интерфейсом и проверкой хронологии операций в главном процессе.
- Renderer: `nodeIntegration=false`, `contextIsolation=true`, `sandbox=true`, CSP, запрет навигации и новых окон. Preload предоставляет только именованные операции; главный процесс проверяет WebContents, главный фрейм и URL отправителя. Пароли/ключи не принимаются.
- Парсеры `electron/sources.ts` читают только разрешённые публичные HTTPS-адреса. Таймаут, ограничение размера ответа и запрет перенаправлений. Разметка сайтов не исполняется, в UI передаётся только текст. Ошибка не очищает старый каталог; источник и статус обновления сохраняются.
- Резервирование через SQLite backup API, а не копирование открытого WAL-файла. Восстановление проверяет целостность, версию, связи, схемы и денежные остатки; заменяет таблицы в одной транзакции после страховой копии.

Для новых площадок нужен адаптер со стабильным ID, раздельными номиналом/ценой/ставкой, временем загрузки и датой фактической котировки. Для брокерского импорта сначала нужны реальные обезличенные примеры отчётов; обязательны предпросмотр, проверка валют/комиссий и ключ дедупликации. Для MOEX понадобится отдельная политика пересчёта цены облигаций, НКД и корпоративных событий.

Тестовый запуск: `INVEST_TEST_MODE=1`, `INVEST_DATA_DIR` задаёт отдельную базу, окно скрыто. Оба параметра работают только в непакетной среде. Реальные личные данные для тестов не используются.

Источники реализации: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [Node SQLite](https://nodejs.org/api/sqlite.html), [Finstore](https://finstore.by/kupit-tokeny/), [Aigenis](https://aigenis.by/), [НБРБ API](https://api.nbrb.by/exrates/rates?periodicity=0).
